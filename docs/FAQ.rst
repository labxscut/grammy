GRAMMy FAQ
==========

How to use GRAMMy for contig abundance estimation?
---------------------------------------------------

It is possible with some hacks. I presupplied the gid_tid.dmp file from NCBI is pre-loaded for common refseq use. In this case you need to name your contigs like:  >gi|contig1, ..., etc in fasta files mimicing NCBI format. And then prepare a separate gid_tid.dmp file for GRAMMy. Assuming your have contig1 and contig2 from species NCBI taxonomy tid 1234; and contig 3 from tid 5678, your gid_tid.dmp file gonna look like:

::

  contig1  1234
  contig2  1234
  contig3  5678

The format is explained in ftp://ftp.ncbi.nih.gov/pub/taxonomy/gi_taxid.readme . Note the abundance estimates are for 1234 and 5678. If you have one contig represent one tid. Just give each contig a unique tid number. You can make up your tid numbers not necessary following NCBI but each tid has to be unique for what it stands for.

How to fix the following import error? ImportError: No module named _gemcore
-----------------------------------------------------------------------------

Problem: Software installation not complete
Solution: Please check if dependencies for GRAMMy have been installed and the C++ module of grammy (gemcore) is properly compiled. http://dl.dropbox.com/u/35182955/Ubuntu_development_environment.html
Steps Taken: Added latest versions of gcc and python compilers.

::

  module add gcc

  module add python

Do I have to provide BLAT/ BLAST results or GRAMMy performs the alignment within?
-----------------------------------------------------------------------------------

No. GRAMMy does not perform sequence alignment for you. Using BLAT/ BLAST you have to align the reads (.fasta) to the target database. The output should be in a tabular format to be readable by GRAMMy.

First, use 'makeblastdb' to create custom database using the (.fna) files 'test.fna.1' generated by grammy_gdt.

::

  makeblastdb –dbtype nucl –in test.fna.1 out db1

Then using megablast align .fasta files to the sequences in the newly created db1.

::

  megablast –d db1 –i c0_L100_N1000_S1.fasta –m 8 –o blast.txt

and finally use

::

  grammy_pre c0_L100_N1000_S1 test -p blast

Why grefs.tgz was not downloaded with the GRAMMy source code?
-------------------------------------------------------------

grefs.tgz is over 2 GB and exceeds GitHub's file size limits, so it is not included in this GitHub mirror.
It can be downloaded separately from http://meta.usc.edu/softs/grammy/grefs.tgz .
